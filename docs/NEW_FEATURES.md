# New Features
* This document outlines the new features introduced in the latest version of our software. Each feature is described in detail, along with its benefits and usage instructions.
* New Feature: Enhanced System Analysis  
  This feature provides advanced tools for analyzing system implementations, mapping all features, integration points, possible configuration items, and dependencies. This process is driven by a comprehensive analysis of the system's architecture, performed by a team of experts with help of powerfull coding model like Claude. The analysis results in a detailed structural report, which maight be used as a basis for Stage 1 (Engeneering Team) of the system configurator. It will be stored in JSON file with predefined structure, which can be used for further processing and analysis. The report will include information about the system's components, their relationships. This tool descovery process runned after each major system update, ensuring that the analysis remains up-to-date and relevant, or in very fisrt onboarding of new system. Our Config Admin feature will be able to read this report and use it to generate a configuration file for the system, which can be used to configure the system's components and their relationships. This feature will help to ensure that the system is configured correctly and efficiently, reducing the risk of errors and improving overall system performance. If Stage 1 detect anu missed feature, requested by the Configuration Admin, it will be reported to the Engeneering Team for further analysis and possible implementation. This process will help to ensure that the system is always up-to-date and meets the needs of its users.
  We probably do not need any UI for this feature, as it is primarily intended for use by system administrators and engineers. However, we may consider adding a simple interface for viewing the analysis report and resulting structure (better in diagram form, for better human understanding), if needed. For example, AENA onboarding started with this kind of analysis, and it was very useful for understanding the system's architecture. In case of Aena we got sample config file, which was used to generate the configuration file for the system, but it not always works, because some needed information maight be stored in database, in some case database schema itself is a data source for the system configurator, and in some cases it is not possible to generate a configuration file without additional information. In such cases, the analysis report will be used to identify the missing information and request it from the system's developers or administrators. This process will help to ensure that the system is always configured correctly and efficiently, reducing the risk of errors and improving overall system performance.
